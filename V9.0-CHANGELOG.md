# SALIM SAUKI DATA V9.0 — GEM CALLING ENGINE

V9.0 upgrades the token-calling pipeline while preserving the V8.8 architecture.

## Added
- Early-entry scoring using real DexScreener pool age and small-cap context.
- Liquidity quality score using liquidity/MC and optional provider history.
- 5m/15m/1h momentum fields and volume acceleration when supplied by DexScreener.
- Volume-quality and abnormal-activity penalties.
- Evidence-aware holder, smart-money and creator sub-scores; missing provider data is never fabricated.
- V9 GEM Score 2.0 with SECURITY, LIQUIDITY, MOMENTUM, SMART MONEY, HOLDERS, CREATOR, VOLUME QUALITY and EARLY ENTRY components.
- False-signal penalty layer.
- Three consecutive qualifying scans for automatic CONFIRMED GEM delivery.
- Auto-signal gate now requires V9 confirmation and blocks high false-signal penalties.
- Signal card exposes V9 component scores and confirmation state.

## Safety / unchanged constraints
- Hard market-cap range remains $10,000–$5,000,000.
- Existing Solana + Base scanning, Helius, FluxRPC, RugCheck, Birdeye, PNL, cleanup, dashboard, API health and Auto Signal Engine are preserved.
- Existing security/honeypot blockers remain authoritative.
- V9 does not claim guaranteed profit and does not invent unavailable holder/wallet/creator data.

## V9.1 — PNL Accuracy & Stability Fix

- PNL now stores the DexScreener pair used at signal entry.
- Current price lookup prefers the original entry pair.
- If the original pair is unavailable, fallback uses the most-liquid valid pool instead of the highest-priced pool.
- Added `pair_address` database migration for existing `pnl_tracking` databases.
- SQLite PNL connections are explicitly closed to avoid connection leaks.
- Existing chain-aware contract tracking, milestones, drawdown alerts, `/pnl` filters, and restart persistence remain intact.
- Added automated PNL tests for pair selection, fallback pricing, migration, and chain-aware tracking.
